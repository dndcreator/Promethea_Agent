# 消息平台接入

平台是现有 Agent 的通信入口，不是另一套 Agent、记忆库或工具系统。

| 平台 | 当前可测试范围 | 接入方式 |
| --- | --- | --- |
| QQ 官方机器人 | 单聊文本；显式授权、独立账号的群 @ 文本 | 已验签 Webhook + 官方 OpenAPI v2 |
| Telegram Bot | 私聊文本 | Secret Token Webhook + Bot API |
| 飞书应用机器人 | 私聊文本；显式授权、独立账号的群文本 | 加密、签名事件订阅 + OpenAPI 回复原消息 |
| 钉钉企业机器人 | 企业内单聊文本；显式授权、独立账号的群 @ 文本 | 签名 HTTP 回调 + 企业机器人 OpenAPI |
| 企业微信自建应用 | 成员向应用发送的私聊文本 | 签名、AES 加密回调 + 应用消息 API |

配置 QQ 请读 [QQ 部署与验收](qq.md)，Telegram 请读 [Telegram 部署与验收](telegram.md)，其他三家请读 [企业平台部署与验收](enterprise.md)。这些均为可测试的真实协议实现，不表示已使用运营方账号完成公网联调。没有个人账号模拟登录、OneBot/NapCat 或“开发中”渠道占位。

## 账号与权限

1. 正常启动 Promethea，确认 HTTP `/health` 已就绪，并能在 Web UI 中完成普通对话。
2. 在项目根 `.env` 配置平台机器人，重启后端。相关键由 `channels/settings.py` 读取，与现有配置一样使用 `__` 嵌套和根 `.env`；显式环境变量优先于 `.env`，`.env` 优先于 `gateway_config.json` 的非敏感渠道参数。
3. 按平台文档配置公网 HTTPS 回调。平台凭证只放根 `.env`，不放个人设置或插件配置 JSON。它们不会进入每个用户的模型配置。
4. 用自己的 Promethea 账号登录，打开 **设置 → 消息平台 → 生成绑定码**，复制 `/bind ...`。
5. 把指令发给自己的机器人，必须是**私聊**。只有经过平台验证的发送者才能完成绑定。绑定码 10 分钟有效，不能绑定到第二个平台身份；同一发送者的重复回调是幂等的。
6. 在设置中刷新状态，然后发送普通文本测试。会话按平台机器人、本地用户、场景和发送者隔离，重新绑定其他用户不会继承另一个人的会话。

更换本地账号前先在旧账号解绑。一个外部身份不能用另一个账号的新绑定码强行覆盖现有归属。

绑定保存在已有 `config/users/identity.sqlite3` 中，不依赖记忆后端。解除绑定会使排队执行和后续投递失去权限；关闭机器人后仍可解绑。删除账号会清理绑定、绑定码和渠道收发数据。个人空间导出不包含机器人凭证、绑定授权或投递队列，迁移后应重新绑定。

没有绑定的消息不会调用模型或自动创建用户。绑定码、控制指令和 Runtime 通知不作为用户对话写入记忆。群共享身份可能访问该身份的记忆和工具，必须使用专用账号及显式成员白名单。

## 敏感操作

敏感工具仍由统一 Runtime 审批。私聊收到 `[Runtime]` 审批通知后，可以发送其中的完整 `/approve <tool_call_id>` 或 `/reject <tool_call_id>`。只作用于同一个已绑定会话的当前待审批操作，复用 `/chat/confirm` 的校验和一次性授权；普通“好的”不会被当作批准。群内不能批准，需回到 Web UI。

正常模型回复原文发送；`[Runtime]` 前缀表示绑定、审批或基础设施通知，不伪装成模型答案。接入平台不会自动跨平台广播 Ambient 通知，也不会自动开启主动推送权限。

## 状态与恢复

消息写入 `.runtime/channels/delivery.sqlite3` 后才确认收到。重复回调不重复执行模型；单个运行时按接收顺序处理。队列默认上限 200，已满返回 503，让平台按其规则重投。

`GET /api/channels/deliveries` 需用户认证，只返回自己的记录。`execution_status` 表示这条请求的 Agent 结果；`state` 表示投递状态，二者不同。

| 投递状态 | 含义 | 处理 |
| --- | --- | --- |
| `queued` / `processing` | 等待或正在调用 Gateway | 等待，不重复发起任务 |
| `ready` / `delivering` | 已有持久回复，等待或正在发送 | 不重新运行 Agent |
| `delivered` | 平台接口确认所有分段发送成功 | 不表示用户已读 |
| `delivery_failed` | 平台明确拒绝，或本地发送约束不满足 | 查错误码；可显式重试持久回复 |
| `uncertain` | 执行或发送时断网、崩溃、取消，结果不明 | 检查会话、Trace 和平台，不自动重跑 |
| `revoked` | 绑定、账号或渠道授权失效 | 重新授权后发起新请求 |

`POST /api/channels/deliveries/{delivery_id}/retry` 只重试 `delivery_failed` 的剩余回复分段，不能重跑 Agent 或重试 `uncertain`。QQ 被动窗口过期时，应从 Web 会话阅读原回复，不会偷偷改用主动消息。过长回复也保留在会话中，报告 `REPLY_TOO_LONG_OPEN_CONVERSATION`，不静默截断。

默认每段 1800 字符，企业微信每段最多 500 字符（为 UTF-8 多字节文本预留空间），最多 4 段。QQ 的 `msg_id + msg_seq` 和飞书的分段 UUID 固定，分段进度持久化。只有明确成功才推进进度。不能宣称跨平台 exactly-once：HTTP 发送后中断无法总是知道对方是否收到，因此进入 `uncertain`。

重启继续 `queued/ready`；中断的 `processing/delivering` 转为 `uncertain`，不盲目重放。待审批内容由原会话保存。收发队列不是 Task checkpoint 的副本，也不宣称恢复任意中断的本机进程。

## 部署边界

- **单机单进程**；OS 文件锁阻止两个 Worker 消费同一队列。不要多 Uvicorn worker，也不要把队列放在 NFS 上模拟分布式系统。
- 只公开已启用平台的 `/api/channels/{channel}/webhook`。通常只需 POST；企业微信还需要同址 GET 验证。回调靠平台签名/Secret Token，不靠用户 JWT；其他后台接口仍保留用户认证。
- HTTPS 代理限制请求体 1 MB，保留认证头、原始 body 和查询参数，并设置速率限制。日志中不要记录 body、签名头、查询串或凭证 URL。钉钉官方 HTTP 签名不覆盖 body，必须端到端使用 HTTPS、保护入口及代理；不能把它描述为原始正文完整性签名。
- 公开网页登录/控制 API 前设置强随机 `AUTH__SECRET_KEY`，不能保留模板占位值；HTTPS 登录应启用安全 Cookie。只公开平台回调不需要把后台控制面一并暴露。
- “已启动”只表示本地传输已配置运行，不证明平台审核、网络或发送权限通过；以真实收发为准。
- 身份库和 `.runtime/channels/` 是敏感运行数据，已被 Git ignore。在线 SQLite 备份应使用 backup API，或停服后复制；不要只复制活动 WAL 数据库主文件。
- 已结束的收发记录启动时按 `CHANNELS__RETENTION_DAYS` 清理，默认 30 天；超过 24 小时的入站消息不接收。未解决的 `uncertain` 不自动清理，会话也不随投递记录清理而删除。
- 模型回合默认超时 240 秒，可设置 `CHANNELS__TURN_TIMEOUT_S`。QQ 发送保守限制为 5 分钟；不承诺长期任务能原路回发，但原回复仍可在会话查看。
- 修改平台凭证、群授权和部署参数后重启后端；普通工具动态注册/热加载不变。

## 验收

1. 正确签名消息获得回复，并出现在同一用户的 Web 历史中。
2. 重复事件不多调用模型或多发回复。
3. 修改 body、错误签名、过期时间戳和错误绑定码不能进入 Agent。
4. 其他用户不能读取或重试自己的投递记录。
5. 敏感工具批准前零调用，正确会话批准后只调用一次。
6. 杀进程或断网后检查 `uncertain`，重启不重复危险动作。
7. 解绑或禁用后，旧队列不继续访问账号和发送结果。

本地协议/集成测试覆盖这些边界，但不能替代运营方凭证、平台审核、网络和真实账号验收。
